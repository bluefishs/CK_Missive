# RWD 現況檢視與調整規劃（2026-09-05）

> owner：「請檢視專案整體 RWD 設計與調整規劃」。
> 本檔＝現況量測 → 問題歸類 → 分階段調整。數字都是 2026-09-05 從原始碼與稽核實測，不是估計。

## 0. 一句話結論

**現在的 RWD 是「窄了就藏」的策略，而藏掉的常常是金額。** 今天兩件事都是它：`/erp/quotations` 的「應付款項」欄、應收分頁的「發票號碼」欄，
都因 `hideOnMobile` 在 **< 992px** 時消失——而 992px 不是手機，是**開著側欄的筆電**。
調整方向：**金額與鍵值永不隱藏；窄螢幕用「收合／換版面」不用「拿掉」**，並把量測做成每週跑的閘門，而不是每次靠 owner 撞到。

## 1. 現況盤點

### 1.1 斷點與判準（`hooks/utility/useResponsive.ts`）

| 名稱 | 條件 | 用途 |
|---|---|---|
| `isMobile` | `< 768px`（AntD `md` 未命中） | 詳情頁 padding／Tabs 尺寸、部分頁面分支 |
| `isTablet` | `768–991px` | 只在表格包裝用 |
| `isNarrow`＝`isMobile‖isTablet` | `< 992px` | **表格 `hideOnMobile` 欄位隱藏門檻** |

判準看的是**視窗寬**（AntD Grid），不是**內容區寬**。側欄展開約 200px ⇒ 1280px 筆電的內容區只剩 ~1080px，
表格已經在擠；1024px 視窗直接進 `isNarrow`，欄位開始消失。

### 1.2 元件與用量（272 個頁面檔）

| 機制 | 檔數 | 觀察 |
|---|---|---|
| `EnhancedTable`（支援 `hideOnMobile`、serverPaged 剝除前端篩選） | 53 | 主力；`hideOnMobile` 標記在 15 檔、約 30 欄 |
| `ResponsiveTable`（`mobileHiddenColumns`） | 8 | 第二套包裝，08-29 才補上 `isNarrow`（weekly 81 守） |
| 裸 `<Table>` | 12 | 多在系統／圖譜頁，`QuotationItemsTab` 是唯一業務頁 |
| 固定 `scroll={{ x: N }}` | 40 | N 多為桌面挑的 900–1530，窄螢幕**設定本身製造橫向捲動** |
| `Col xs=` 網格 | 85 | 網格層做得算齊 |
| `ResponsiveFormRow` | 13／58 個表單頁 | 表單列響應式只覆蓋 22% |
| `isMobile` 分支 | 45 | 各頁各寫，沒有共同的「窄螢幕該長什麼樣」 |

| 全域 CSS `@media` | 30 處（`styles/responsive.css` 7 段） | 有斷點骨架，但頁面層很少用它 |

### 1.3 被 `hideOnMobile` 藏掉的欄位（< 992px 消失）

| 頁 | 藏掉的欄 | 該不該藏 |
|---|---|---|
| `/erp/quotations` | 協力廠商 | 可（次要） |
| `/erp/vendor-accounts` | 統一編號、合作案件數、**已付總額、付款率** | **金額不該藏** |
| 應收／應付分頁 | 請款日期、收付款日期 | 日期可折進主欄，不該直接拿掉 |
| 承攬案各分頁（人員／廠商／公文／附件） | 部門、聯絡方式、加入日期、狀態、合作期間… | 可，屬輔助資訊 |
| 桃園派工 | 批次、序號、說明、關聯公文 | 序號是鍵，不該藏 |

**已在今天處理**：發票號碼欄（改與動作欄合一）、應付款項欄（改常駐）。

## 2. 問題歸類

| # | 問題 | 影響 |
|---|---|---|
| P1 | **隱藏門檻 992px 涵蓋筆電** | 金額欄在桌面就消失，使用者以為功能沒做 |
| P2 | **藏欄位的判準是「寬度」不是「重要度」** | 應付、付款率、序號這類鍵值被藏；協力廠商這類次要的反而有時留著 |
| P3 | 判準看視窗寬不看內容區寬 | 側欄展開時實際可用寬度更小，設定卻以為還是桌面 |
| P4 | 兩套表格包裝＋裸 Table | 修好一套另一套重演（weekly 81 就是這樣來的） |
| P5 | 固定 `scroll.x` 40 檔 | 窄螢幕必橫捲；手機上表格不可讀 |
| P6 | 側欄 768–1199 固定展開 | 平板與小筆電內容區被吃掉 200px（手機已是 Drawer） |
| P7 | 表單只有 22% 用 `ResponsiveFormRow`；Modal 46 檔 | 手機填報體驗不一致 |
| P8 | 沒有頁面級量測閘門 | 問題只能靠人撞到 |

## 3. 設計原則（提案，待 owner 拍板）

1. **金額、鍵值、狀態永不隱藏**（承攬金額／應收／應付／發票號碼／案號／序號）。窄螢幕改「折進主欄的第二行」或「換卡片版面」。
2. **隱藏只給輔助資訊**，且門檻降到 **< 768px**（真手機），不再包含平板與筆電。
3. **判準改看內容區寬度**（`ResizeObserver` 量 `Card`／`Table` 容器），側欄開合、視窗大小都能正確反應。
4. **一套表格包裝**：業務頁統一 `EnhancedTable`；`ResponsiveTable` 併入；裸 `Table` 只准在系統頁。
5. **欄位分三級**：`primary`（永不藏）／`secondary`（< 768 折進主欄）／`aux`（< 768 隱藏）。用一個屬性 `priority` 取代布林 `hideOnMobile`。
6. **手機列表用卡片**：< 768px 的業務列表（報價單／承攬案／PM 案／帳款）改 `MobileListCard`（標題＋兩行摘要＋金額），表格只在 ≥ 768 顯示。
7. **側欄**：< 1200px 自動收合、< 768px 改 Drawer。
8. **量測進排程**：每週對 20 個業務頁在 390／768／1024／1366 四個寬度量「整頁溢出 px」「被藏的 primary 欄數」，任一 > 0 即 RED。
9. **裝置偵測＋可強制**（09-05 owner 提問後加）：`useResponsive` 以 UA-CH `userAgentData.mobile` → UA 字串 → 粗指標＋觸控偵測登入裝置；行動裝置橫放到 768–991px 仍走手機版面。右上角使用者選單「版面：自動／手機版／桌面版」可強制，存 localStorage 跨頁記住；登入紀錄本來就存 `device_info`（UA）供事後統計。

建議順序＝表格（P1）→ 量測（P4 已在）→ 手機卡片（P2）→ 表單（P3），因為使用量集中在列表頁。

## 5. 不做的

- 不另開手機版站台或 App：同一套頁面、同一份資料，只換版面。
- 不把「隱藏」當 RWD 手段：任何會讓使用者以為「功能沒做」的收斂都不用。
- 不對 272 頁全面重做：只針對業務頁（ERP 26／承攬 6／PM 4／公文 5／桃園 5／人員廠商 6 ≈ 52 頁），系統頁維持現狀。
