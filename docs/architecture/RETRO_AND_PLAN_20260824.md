## 二、八條判準（都是實測換來的，不是推論）

1. **量測方法沒先驗，結論就不可信。** 同一輪我有四次機會宣告「已經擋住了」而
   每次都是錯的：Cloudflare 擋掉 `Python-urllib` 預設 UA（全 403）、bash
   `while read` 裡的 curl 吃掉 stdin（全 000）、連續快打觸發速率限制、
   token 解析寫壞。**四種失敗都長得像「安全」。**
2. **CSRF 不是認證。** CSRF token 端點是刻意公開的，未登入就能拿。
   判準：**帶著公開可取的 CSRF token 之後仍然 401 才算真的擋住。**
   ⚠️ 適用性取決於該 repo 的檢查順序 —— lvrland 是認證先於 CSRF 所以不適用。
3. **在有豁免的環境驗證安全機制等於沒有驗證**（本機 `AUTH_DISABLED=true`）。
4. **座標系有兩半**：公開白名單一半、**認證函式名單另一半**。
   只帶白名單，lvrland 會拿到 49 條假陽性。
5. **工具只看得到它知道要看的地方。** 我的稽核只掃 `/api/*` ⇒ `/metrics`
   公網外洩了三天而工具在設計上看不到它。
6. **非瀏覽器消費者是盲區**（pile 指出）：Prometheus／webhook 這類基礎設施
   抓取器不在前端消費鏈裡，前端 grep 與 dependency 樹都看不到。
7. **綁定不是相等**（FacilityDev 指出）：語意版號答「這一輪做了什麼」、
   commit 答「跑的是哪一份程式碼」，兩者不比對相等，但綁在一起才答得出
   「線上這個 commit 是不是 v6.60」。
8. **失敗要有上限。** pile 的應用被單一請求卡 23 小時（無 request timeout）、
   備份排程 `ExecutionTimeLimit=PT72H`（形同沒有上限）—— 同一個形狀。

## 三、三種發現方式（本輪最重要的一條，已進 OPEN_ITEMS 判準 14）

| 方式 | 抓到的是什麼 | 本輪實例 |
|---|---|---|
| **自查** | 我**已經在看**的東西壞了 | 都有第二個來源或它會大聲失敗（NAS 掃描說「空」但稽核說 1528） |
| **互查** | 我**連那個維度都沒有** | 認證名單那一半（lvrland）／baseline 假理由（FacilityDev）／`/metrics`（pile） |
| **⭐互查提問＋自查作答** | 對方**看不到我的系統**，但說出了值得我自己查一遍的問句 | AaaP 報他們的版次漂移 → 我查出自己更嚴重（`health.version` 是 `None`） |

**第三類槓桿最大**：不需要存取權、不需要雙方同時在跑、**可以留在文件裡等下一個人**。
本輪四次裡有三次，發現者看不到被發現者的系統。

⚠️ **界限**（AaaP 立的，我同意）：互查依賴對方當時剛好在跑，**不能取代自查、
也不寫成流程** —— 寫成流程就會變成一個沒有人跑得動的儀式。

## 五、作業規劃（優先序，回歸 Missive）

### 第一優先——資安收尾，因為它有明確終點

**C2 混雜 router 核實**。我 08-21 改了 11 個 router 檔加認證，pile 的經驗說
這種做法會誤擋同檔案裡的公開端點。**這是我自己造成的風險，且未驗證。**
做法：逐一列出那 11 個檔的端點，比對前端消費鏈與 `@auth public` 等效標記。

**C1 POST 慣例補檢核**。判準：非白名單的 GET 端點一律 RED，白名單每條寫明
「為什麼只能 GET」。已知 15 條是外部工具強制（healthcheck／SSE／Swagger），
6 條要處理。**成本低、終點明確。**

### 第二優先——把「只驗過一種人」補上

**C3 走查雙身分**。這是 08-20「同仁變成代碼」的根本盲區，也是 08-10
「員工看得到卻用不了」的同一維度換了地方長出來。引擎跨 5 repo 共用，
所以這一項做完**五個 repo 同時受益**——槓桿最大的一項。

⚠️ 難點在斷言要能分辨「這個頁面該看不到」與「該看到卻是空的」。

### 第三優先——業務缺口

**C5 標案決標資料**。109,344 筆標案裡 `award_amount`／`bidders` 全部 0，
而分析功能恆為 0 且不報錯。三條取得路徑都還沒驗成，`TENDER_DATA_GAPS.md`
建議先驗一筆 PCC 決標頁再談批次。**這是唯一有業務價值的一項**，但它需要
先確認資料抓得到——不確認就做等於再造一個分析不存在資料的功能。

### 不做的（明確寫下來，免得下次又提）

- **`.claude/rules/` 可推導性審查**（C6）：12 檔全是規範與判準，不是可推導內容。
  /doctor 的檢查 3 對它不適用。**除非 owner 要求，不動。**
- **廠商重複比對**：owner 08-20 已決定不做（5 組相似名稱裡只有 1 組是真重複，
  自動判重會產生 4/5 假陽性）。
- **跨 repo 代改**：埠綁定、備份路徑、逾時上限——只通報不代動。
