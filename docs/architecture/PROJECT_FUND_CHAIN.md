## 1. 鏈路實況

```
邀標案件 pm_cases 253（已成案 50）
   └─ case_code ─┐
                 ├→ 報價單 erp_quotations 256（已確認 251）
                 │     └─ erp_quotation_id ─┬→ 請款 erp_billings 59（已收款 38）
                 │                          └→ 應付 erp_vendor_payables 37（已付 33）
                 │                                    │
   承攬專案 contract_projects 88 ────────────────────┤
   （project_code + case_code，已結案 75／執行中 13）  │
                                                      ↓
                              統一帳本 finance_ledgers 81（收入 39／支出 42）
                              來源：erp_billing 39｜erp_vendor_payable 33｜expense_invoice 9
```

### ⚠️ 關聯鍵的實情：請款與應付掛在**報價單**，不是專案

`erp_billings` 與 `erp_vendor_payables` **只有 `erp_quotation_id`**，
沒有 `project_code`。要看某個專案的資金必須走**三跳**：

```
contract_projects.project_code → .case_code → erp_quotations.case_code
                                            → .id → billings / payables
```

⇒ 任何「這個專案收了多少付了多少」的查詢都要記得這一跳，
**漏掉就會得到 0 而不是報錯**。

其中有明確合約金額的 4 案：

把它們算進來會讓這條每天報一個不能行動的數字。

### 這份盤點回答了「還缺什麼」

「掌握專案資金管理」的**主幹已經通**（報價 → 請款 → 帳本，0 缺口）。
缺的是**三個讓人能往下追的維度**，而它們的共同點是**能力都已經建好**：

1. **報價明細 0 筆** ⇒ 只有總額、**無法逐項看成本**
   （順帶：`total_price` 的成本四欄也全是 0 ⇒ 毛利恆等於營收）
2. **里程碑 0 筆** ⇒ **無法把請款時點連到進度**
   ⚠️ 而 `pm_milestones` 連金額欄位都沒有 —— 要做「里程碑請款」需先加欄位
3. **案件附件僅 4 筆** ⇒ 合約與客戶回簽沒有留存，**成案判準只能靠猜**

### ⚠️ 刻意不為這三項各加一條檢核

已加的兩條（報價明細、執行中專案金流）足以代表這個家族。
再加就變成一長串 YELLOW，而**一長串 YELLOW 的下場是沒有人看**。
⇒ 這一節本身就是那個訊號：**盤點放在文件裡，決策留給 owner**。
