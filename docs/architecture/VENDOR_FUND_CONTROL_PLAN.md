# 協力廠商經費：兩端如何對應管控

> 建立：2026-08-27
> owner：「`/erp/quotations/168?tab=payable` 應付帳款 tab 需填列**經費付款期別**，
> 與 `/contract-cases/187?tab=vendors` 協力廠商 tab 須填列**合約經費**，
> 如何對應管控避免兩端不一致、等經費統整有所差異，請規劃評估」
>
> **所有數字都是 2026-08-27 實測。**

## 1. 兩端存的是什麼

| 畫面 | 資料表.欄位 | 語意 | 筆數 |
|---|---|---|---:|
| 協力廠商 tab | `project_vendor_association.contract_amount` | 與該廠商簽的**合約總額**（一次） | 33 |
| 應付帳款 tab | `erp_vendor_payables.payable_amount` ＋ `payable_period` | 依期別**分次應付**（多筆） | 39 |

**正確的關係是一個等式**：

```
Σ payable_amount（同一專案、同一廠商）  ＝  contract_amount
```

⇒ 它們**不是兩份重複資料**，是「總額」與「拆期」的關係。
問題不在於存了兩份，在於**沒有任何東西在看那個等式**。

### ⚠️ 兩端沒有共同外鍵，只能靠 case_code 相接

```
project_vendor_association.project_id → contract_projects.case_code
                                              ↕
erp_vendor_payables.erp_quotation_id  → erp_quotations.case_code
```

**三跳**。漏掉這一跳的查詢會**回 0 筆而不是報錯**，看起來像「完全一致」。

## 2. 實測：問題比「不一致」更基本 —— 兩端幾乎沒有交集

```
協力廠商登記              33 筆
兩端都有                   3 筆   ├ 金額一致 2   └ **不一致 1**
只有協力廠商、無應付       30 筆   └ 其中**只有 1 筆**填了合約經費
只有應付、協力廠商未登記   28 組
```

### 已經真實發生的不一致

```
CK2026_PM_01_005  政威資訊顧問有限公司
  協力廠商 tab 填    $2,000,000
  應付帳款 tab 合計  $1,000,000（2 期，兩期都有填期別）
  ⇒ 差 $1,000,000，而先前沒有任何東西在報
```

⇒ owner 擔心的事**已經發生了**，只是沒有人看得見。

### 另一個更根本的事實

33 筆協力廠商登記裡**只有 1 筆填了 `contract_amount`**。
⇒ 「合約經費」這個欄位**幾乎沒有人在填**，
而 28 組應付**完全沒有在協力廠商那邊登記過**。

**兩個 tab 各自為政，不是同步失敗，是從來沒有同步過。**

## 3. 三個方案

### 方案 A：合約經費改為唯讀，由應付分期加總得出 ⭐建議

```
協力廠商 tab 的「合約經費」 = Σ 該廠商在本專案的 payable_amount（唯讀顯示）
```

* **優點**：等式**結構上不可能違反** —— 只有一個地方能填，另一邊是算出來的。
  這與本 repo 既有的作法一致（線上報價明細上線後，`total_price` 由小計加總得出、
  不再獨立維護）。
* **代價**：不能「先簽約定總額、之後才拆期」——
  而實測 33 筆裡只有 1 筆填了總額，**這個流程實際上沒有人在用**。
* **風險**：那 1 筆（政威 $2,000,000）會變成顯示 $1,000,000。
  ⇒ 上線前要先問 owner：**哪一個數字是對的**。

### 方案 B：兩端都可填，不一致時當場說出來

* 協力廠商 tab 顯示「合約經費 $2,000,000（應付已建 $1,000,000，**差 $1,000,000**）」
* **優點**：保留「先談總額、後拆期」的流程；差額本身就是有用的資訊
  （＝還沒建的應付期數）。
* **代價**：兩份數字仍然存在，仍可能有人只改一邊 ——
  但至少**畫面會說**，而不是靜靜地不一致。

### 方案 C：只做檢核，畫面不動

* **已實作**（見 §4），零風險、零流程變更。
* **不足**：它是**事後**發現，而不是**當場**阻止。
  使用者要等到週檢核才知道自己填錯。

## 6. 判準

1. **兩份數字不是問題，沒有人看那個等式才是問題。**
   總額與分期本來就該同時存在，關係是「加總相等」。
2. **「不一致」的前提是兩邊都有值** —— 而實測 33 筆裡只有 1 筆填了合約經費。
   ⇒ 先問「這個欄位有沒有人在填」，再問「填的對不對」。
3. **未填與填錯要分開判** —— 混在一起會產生 29 筆紅色，
   而那 29 筆沒有一筆是矛盾。
