`tender_type` 分布也印證同一件事：

```
公開招標公告          77,805
限制性招標             5,781
限制性招標更正公告        82
經公開評選…限制性招標      45

更正決標公告               7   ← 決標類只有這 7 筆
```

**抓取端只抓招標公告，從來沒有抓決標公告。**

## 2. 連帶影響：分析功能在分析不存在的資料

`services/tender/analytics.py` 有完整的決標分析邏輯
（`本週決標`／`得標廠商`／`無法決標` 分類、`analytics_price.py` 的
「預算/底價/決標金額」比較），判斷依據是 `type` 欄位含「決標」。

而資料庫裡決標類只有 7 筆 ⇒ **那些統計恆為 0 或近乎 0，而不會報錯**。
這不是程式壞了，是它要分析的資料從來沒有進來。

## 3. 本輪已解決的部分：預算金額

⚠️ **這推翻了 `L77`「enrichment 死結」的一部分。**

L77 說的是**採購性質／底價**需要 `org_id`，而 org_id 只在被反爬限流的頁面上
—— 那部分仍然成立。但**預算金額就寫在 PCC 詳情頁本文，不需要 org_id**。

實測（2026-08-19，三筆、間隔 3 秒）：

```
NzEzMDQ3MzI= → HTTP 200 / 1.2s / 預算 606,020
NzEzMDA1NzQ= → HTTP 200 / 0.2s / 預算 4,000,000   （與該案 ezbid 版本一致）
NzEyODY4Nzk= → HTTP 200 / 0.3s / 預算 625,000     （與該案 PM 合約金額一致）
```

無驗證碼、無「查詢過於頻繁」。三個獨立來源交叉印證 ⇒ 不是巧合。

**既有程式只把 PCC 詳情頁的網址組給前端，從來沒有去抓那一頁的內容**
（`services/tender/search.py` 的 `pcc_url` 只是個字串）。
已改為：沒有金額時才抓、抓到寫回 DB（同一筆最多抓一次）、逾時 8 秒、
失敗不擋詳情頁。

## 4. 決標資料要怎麼拿：三條路都還沒驗成

| 路徑 | 現況 | 備註 |
|---|---|---|
| **g0v API** | ❌ `pcc.g0v.ronny.tw/api/searchbytitle` **回 HTML 不是 JSON**（2026-08-19 實測 200 / 2,867 bytes / `text/html`） | CLAUDE.md 記載「暫依 g0v API（1-5 天延遲）」，該端點現況需重新確認 |
| **PCC 決標公告頁** | 未驗 | 招標詳情頁已證實可抓（見 §3），決標公告是另一組網址，值得用同樣方式試 |
| **ezbid** | 部分 | ezbid 有決標分類，但我們只抓了「最新招標」清單 |

### 為什麼這件事值得做

決標資訊（誰得標、多少錢、幾家投標）是**業務判斷的核心**：
沒有它就無法回答「這個機關的案子通常誰在做」「我們的報價落在什麼區間」。
目前 `/tender` 的價格分析、戰情室、對手分析都建立在這批不存在的資料上。
