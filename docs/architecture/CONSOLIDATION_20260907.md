## 二、收斂 A：角色是權限的唯一來源

| 此前 | 現在 |
|---|---|
| `role_permissions`／`users.permissions`／`users.is_admin` 三份互不牽動 | 角色是唯一來源；使用者清單與旗標**由角色推導** |
| 儲存角色後要人按「同步」 | 儲存即同步（`update_role_permissions` → `sync_users_to_role_permissions`） |
| 改使用者角色，權限清單不動 | 改角色即推導清單與旗標（`user_management.update_user`） |
| 建立使用者硬抄一份預設清單（與角色差兩項） | 由 `user` 角色推導 |
| `is_admin_user` ＝ 旗標 OR 角色（前後端各一份） | **只看角色**（`dependencies.py`／`authService.ts`／`usePermissions.ts` 同步） |

**證據（容器內實跑）**：角色加一碼 → 6/6 業務同仁立即拿到，移除 → 0；張浩翊 staff→user→staff 權限 17→5→17；
role=staff 但 is_admin=true 打使用者管理 → 403。單元測試 `test_admin_role_only.py`。

保留的顯性例外：`user_permissions.py` 逐人覆寫。它現在是**唯一**能讓使用者偏離角色的路徑，weekly 119 ③ 以 YELLOW 列出。

## 三、收斂 B：選單表是選單／路由守衛／API 三邊的唯一來源

| 層 | 從哪裡讀 |
|---|---|
| 選單顯示 | `site_navigation_items.permission_required`（原本就是） |
| 路由守衛 | 同上（09-07 `useNavPermissionGate`） |
| API | `require_page_permission("/erp/ledger")` → `app/core/capabilities.py` 快取的選單表 |

程式碼裡只留路由結構（API 前綴 → 頁面路徑）。ERP 15 支子路由、圖譜 20 支讀取端點已改。
快取：啟動載入（62 頁）／選單儲存後 refresh／60 秒保底 TTL。失效方向＝放行（不自己發明限制），
但被引用而選單表缺宣告的頁面在啟動時 WARNING。

**證據**：把 `/erp/ledger` 選單宣告改成 `admin:settings` → 財務打 API 200→403 → 還原 200。**零程式碼、零部署。**
三身分 × 8 端點與收斂前守門結果完全相同。單元測試 `test_capabilities.py`。

## 四、剩餘的第二份宣告（誠實列出）

| 宣告 | 現況 | 建議 |
|---|---|---|
| 前端 `PERMISSION_CATEGORIES` | 只剩**標籤與分類**（行為已不依賴它） | 可改為從 DB 權限碼＋標籤表產生；weekly 119 ① 續守 |
